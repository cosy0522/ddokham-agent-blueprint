# 갈래 판정 규칙

만들 물건의 종류를 정하는 규칙이다.
갈래는 **스킬 · 도구 · 에이전트** 셋 중 하나이며, 부품 판정보다 **먼저** 확정한다.
갈래가 정해져야 부품 판정 범위가 정해지고, 세팅 프롬프트의 본문도 갈라진다.

판정 결과는 `갈래.판정` · `갈래.이유` · `갈래.선택` · `갈래.원래권장` 네 필드에 기록한다.

---

## 1. 판정에 쓰는 답

갈래를 판정하려고 질문을 새로 만들지 않는다.
이미 받은 답만으로 판정한다.

| 질문 | 저장되는 곳 | 판정에서 쓰는 방식 |
|------|-----------|-----------------|
| Q2 완성되면 이건 어디로 가나요 | `결과물.전달방식` (배열) | 어떤 값이 들어 있는지 |
| Q3 이건 얼마나 자주 만드시나요 | `결과물.주기` | 자주 도는 쪽인지 아닌지 |
| Q4 만들 때마다 새로 받는 자료는 어디서 가져오나요 | `입력.매번바뀜[].출처` | 서로 다른 출처의 **개수** |
| Q7 지금은 이런 순서로 만드시나요 | `과정[]` | 단계 **개수** + `담당` 값 + 단계 성격 |
| Q11 이건 어떻게 시키실 건가요 | `구성.실행방식` | 값 자체 |

### Q9는 갈래 판정에 쓰지 않는다

되돌아온 경험(`반려사유`)은 **부품 `평가담당`을 켤 근거일 뿐이다** (`part-rules.md` 5절).
아래 어느 게이트에서도 `반려사유`를 보지 않는다.

되돌려받은 적이 있다는 이유로 갈래를 올리면, 스킬 하나로 끝날 일에 폴더와 지시가 붙는다.
그 사람이 겪은 것은 "다시 손봤다"이지 "더 큰 걸 만들어야 한다"가 아니다.
단순한 업무에 에이전트를 세우지 않는 것이 이 판정의 목적이다.

### 세는 법

**출처 개수** — `입력.매번바뀜[].출처`의 서로 다른 값의 개수를 센다.
같은 출처에서 파일 세 개를 받으면 출처는 1곳이다.
`"미정"`은 개수에 넣지 않는다.

**단계 개수** — `과정[]`의 길이.

**사람 확인 지점 있음** — `과정[].담당`에 `사람` 또는 `AI+확인`이 하나라도 있으면 참.

**판단·글쓰기 단계 있음** — `과정[].이름`이 무엇을 쓸지 고르거나 문장을 짓는 일이면 참.
해당하는 단계 이름의 예: 무엇을 넣을지 고르기, 초안 쓰기, 정리해서 설명 붙이기, 우선순위 정하기, 여러 자료를 요약해 한 장으로 줄이기.
해당하지 않는 단계 이름의 예: 모으기, 합치기, 계산하기, 형식 바꾸기, 이름 바꾸기, 표로 옮기기.

**이미 만들어 둔 것에서 바뀐 부분만 고쳐 넣는 일은 판단·글쓰기가 아니다.**
무엇을 쓸지 고르는 게 아니라 달라진 값을 옮기는 일이다.
지난번 것을 열어 올해 것으로 갈아 끼우는 일이 여기 해당한다.

**기계적 반복** — 아래 셋이 **모두** 참일 때만 참이다.

| 번호 | 조건 |
|------|------|
| 가 | `과정[]`의 모든 단계가 위 "해당하지 않는" 쪽이고, 판단·글쓰기 단계가 0개다 |
| 나 | 결과물 한 건을 만들려고 파일·페이지·줄을 여럿 다뤄야 한다. 손만 많이 가는 일이다 |
| 다 | `결과물.주기`가 자주 도는 쪽이다 |

**자료 한두 개로 결과물 하나를 만드는 일은 기계적 반복이 아니다.**
손이 많이 가는 일이 아니라 매번 같은 서식에 맞추는 일이고, 이건 스킬 쪽이다.
「나」를 빼고 보면 서식 맞춰 문서 하나 만드는 일까지 도구로 넘어간다.

### 주기는 글자가 같은지 보지 않는다

`결과물.주기`는 표현이 조금씩 다르게 저장된다.
같은 뜻인데 `매월`로 적힐 때도 있고 `매월 1회`로 적힐 때도 있다.
보기 문구와 글자가 똑같은지 맞춰 보면, 같은 뜻인 답이 규칙에 안 걸리는 일이 생긴다.

**낱말이 들어 있는지로 본다.**

| 값에 이 낱말이 있으면 | 판정 |
|------------------|------|
| `주` · `월` · `건별` · `그때그때` | 자주 도는 쪽 (「다」가 참) |
| `분기` · `반기` · `연` · `년` | 드물게 도는 쪽 (「다」가 거짓) |
| 둘 다 없거나 `미정` | 신호 없음으로 본다 (「다」가 거짓) |

두 쪽 낱말이 다 들어 있으면 드물게 도는 쪽으로 본다.
같은 방식을 게이트 4의 드물게 도는 주기 판단에도 그대로 쓴다.

## 2. 판정 절차

위에서부터 순서대로 본다.
먼저 걸리는 게이트에서 멈추고, 아래 게이트는 보지 않는다.

### 게이트 1 — 도구 (강한 신호)

둘 중 하나라도 참이면 **도구**로 판정한다.

| 번호 | 조건 |
|------|------|
| T1 | `결과물.전달방식`에 `"다른 사람이 각자 실행해서 쓴다"`가 들어 있다 |
| T2 | `구성.실행방식`이 `"다른 사람이 각자 실행"`이다 |
| T3 | 기계적 반복이 참이다 (「가」·「나」·「다」가 모두 참) |

T1·T2가 게이트 1에 있는 이유는, 남이 각자 돌려야 하는 일은 스킬로도 에이전트로도 답이 안 나오기 때문이다.

**T3 하나만 참일 때는 단서가 붙는다.**
`결과물.전달방식`에 `"누군가에게 보낸다"`가 들어 있으면 T3로는 여기서 멈추지 않고 아래 게이트로 내려간다.
도구 갈래에는 보내는 일을 맡길 부품이 없어서, 여기서 멈추면 설계도에 보내는 단계를 그릴 자리가 사라진다.
T1·T2에는 이 단서를 적용하지 않는다. 남이 각자 돌려야 하는 일은 그것대로 도구가 맞다.

### 게이트 2 — 스킬

네 조건이 **모두** 참이면 **스킬**로 판정한다.

| 번호 | 조건 |
|------|------|
| S1 | 출처 개수가 1곳 이하 |
| S2 | 단계 개수가 3개 이하 |
| S3 | 사람 확인 지점 없음 (`담당`이 전부 `AI`) |
| S4 | `결과물.전달방식`이 `["파일로 남는다"]` 하나뿐 |

### 게이트 3 — 에이전트

아래 신호가 **하나라도** 참이면 **에이전트**로 판정한다.

| 번호 | 조건 |
|------|------|
| A1 | 출처 개수가 3곳 이상 |
| A2 | 판단·글쓰기 단계가 있음 |
| A3 | 사람 확인 지점이 있음 |
| A4 | `결과물.전달방식`에 `"누군가에게 보낸다"` 또는 `"여러 사람이 보는 화면에 올린다"`가 있음 |

**신호는 받은 답에 뚜렷할 때만 센다.**
참인지 아닌지 갈리지 않는 신호는 세지 않는다.
특히 A2는 손이 가는 일을 판단이라고 부르지 않는다. 무엇을 고르거나 문장을 짓는 단계가 실제로 있어야 참이다.
근거가 흐릿한데 세면, 스킬로 끝날 일이 신호 하나에 밀려 제일 큰 갈래로 올라간다.

### 게이트 4 — 애매할 때

세 게이트 어디에도 딱 걸리지 않는 경우다.
예를 들면 출처가 2곳이고 단계가 다섯 개인데, 판단 단계도 사람 확인도 없고 파일로만 남는 경우다.

이때는 **낮은 쪽을 먼저 권한다.**
순서는 스킬 → 도구 → 에이전트다.

| 남은 상황 | 판정 |
|----------|------|
| 에이전트 신호(A1~A4)가 0개이고, 걸리는 게 단계 수뿐 | **스킬** — 단계를 줄여 시작하자고 권한다 |
| 에이전트 신호가 0개이고, 여러 건을 모아 기계적으로 처리하는데 `결과물.주기`가 드물게 도는 쪽이라 게이트 1에 안 걸림 | **도구** |
| 위 둘로도 안 갈리면 | **스킬** |

**낮은 쪽을 먼저 권하는 이유는 유지비다.**
큰 걸 만들면 고칠 것도 크다.
스킬 하나는 고칠 데가 한 군데지만, 에이전트는 폴더·지시·부품이 다 고칠 거리가 된다.
작게 만들어 쓰다가 부족하면 올리는 편이, 크게 만들어 놓고 안 쓰는 것보다 낫다.

### 답이 비어 있을 때

판정 근거가 되는 답이 `미정`이면, 그 신호는 **없는 것으로 본다.**
없는 것으로 보면 자연히 낮은 갈래로 기운다.
시간이 남으면 그 항목 하나만 다시 묻고, 시간이 없으면 `미정` 배열에 항목 이름을 남기고 그대로 판정한다.

## 3. 갈래가 정해진 뒤 채우는 것

| 갈래 | `구성.폴더` | `구성.사람확인지점` | `구성.실행방식` |
|------|-----------|------------------|-------------------|
| 스킬 | `[]` | `[]` | 항상 `"Claude 계정에 올려두고 말로 시킨다"` |
| 도구 | `[]` | `[]` | Q11의 답 그대로 |
| 에이전트 | 폴더 이름 배열 | 사람이 볼 단계 | Q11의 답 그대로 |

폴더를 만들지 않는 갈래에서 `폴더`를 채우지 않는다.
만들지도 않을 폴더 이름이 설계도에 뜨면 사용자가 그게 이미 있는 줄 안다.

### 스킬 갈래에서는 Q11의 답을 그대로 옮기지 않는다

Q11에서 `폴더에 파일 넣고 시킨다`나 `정해진 때에 알아서`를 골랐더라도, 갈래가 스킬이면 `구성.실행방식`은 위 문장으로 적는다.
스킬 갈래는 `폴더`가 빈 배열이라 넣을 폴더가 없다.
폴더로 시킨다는 말만 남으면 설계도에는 폴더가 없는데 쓰는 법에는 폴더가 나온다.

폴더를 두고 돌리는 쪽을 원한 것이었다면 그건 갈래를 올리자는 뜻이다.
7절의 절차로 확인하고, 올리기로 하면 그때 Q11의 답을 그대로 쓴다.
확인 없이 실행 방식만 바꿔 두지 않는다.

## 4. 스킬로 판정됐을 때 반드시 말해 줄 것

스킬 갈래는 **PC에 아무것도 세팅하지 않는다.**
스킬 하나를 만들어 Claude 계정에 올려 두고 쓴다.
이 한 줄을 빠뜨리면 사용자는 "나만 작은 걸 받았다"로 받아들인다.

판정 문장 뒤에 아래 네 가지를 그대로 붙여 말한다.

| 이점 | 말해 줄 문장 |
|------|-----------|
| 어디서든 쓴다 | 회사 PC든 집이든 모바일이든, 로그인만 하면 그대로 있습니다 |
| 오늘이 지나도 남는다 | PC에 깐 건 재설치하거나 포맷하면 날아가지만, 계정에 올린 건 남습니다 |
| 동료에게 주기 쉽다 | 파일 하나만 건네면 그 사람도 자기 계정에 올려서 씁니다 |
| 유지비가 없다 | 폴더도 지시 파일도 없습니다. 고칠 게 스킬 하나뿐입니다 |

그리고 이 갈래는 **오늘 안에 끝나는 유일한 갈래**라는 점을 덧붙인다.

## 5. 도구로 판정됐을 때 반드시 지킬 것

**로컬 웹앱이 기본값이다.**
주소를 열고 버튼을 누르면 처리되는 화면을 만든다.

**명령어를 직접 치게 하는 선택지는 없다.**
만드는 과정에서 중간 산출물로 존재할 뿐, 사용자에게 주는 형태가 아니다.
사용자에게 "이 명령을 실행하시면 됩니다"라고 안내하지 않는다.

실행 파일로 올리는 조건은 하나뿐이다.

| 단계 | 언제 |
|------|------|
| `"로컬 웹앱"` | 기본값. 내가 쓰거나, 설치가 가능한 사람이 쓸 때 |
| `"실행 파일"` | 나눠줄 상대가 **설치를 못 한다는 사실을 받았을 때만** |

### 이미 받은 답 안에 있으면 그게 이유다

**설치를 못 한다는 말을 이미 들었으면, 그 문장이 곧 "웹앱으로는 왜 안 되는지"다.**
그 문장을 그대로 한 줄로 다듬어 `부품.혼자도는도구.웹앱으로안되는이유`에 넣고 `단계`를 `"실행 파일"`로 적는다.
같은 사실을 다시 묻지 않는다.

어느 질문의 답이었는지는 따지지 않는다. 인터뷰 도중 어디서 나온 말이어도 된다.
사용자가 이미 한 말을 못 들은 것으로 치면, 근거가 있는데도 로컬 웹앱에 머문다.
그러면 설치를 못 하는 사람들에게 열리지 않는 화면을 만들어 주게 된다.

### 그런 말이 없으면 로컬 웹앱이다

받은 답 어디에도 설치를 못 한다는 사실이 없으면 `단계`는 `"로컬 웹앱"`이다.
이때 설치가 되는지를 새로 묻지 않는다.
남에게 나눠 준다는 것만으로는 올리지 않는다. 그 사람들이 설치를 할 수 있으면 웹앱이 더 낫다.

실행 파일은 만들기가 무겁고 고치기도 어려워서, 근거 없이 가면 손해가 크다.
사용자가 나중에 설치가 안 된다고 말하면, 그때 근거가 채워진 것으로 보고 올린다.

무엇을 설치 못 한다는 사실로 보는지는 `part-rules.md` 7절의 표에 있다.
두 파일의 판정은 같아야 하므로, 판정할 때는 그 표를 기준으로 본다.

## 6. 판정을 말하는 문장 틀

판정만 던지지 않는다.
**이유를 함께 준다.**
강요하면 반발하고, 이유 없이 따르게 하면 배우는 게 없다.

`{이유}`에는 `갈래.이유`에 넣을 문장을 그대로 쓴다.
이유는 판정 근거가 된 답을 인용해 한 문장으로 만든다 (예: "자료가 한 곳이고 중간에 확인할 지점이 없어서").

### 스킬

> 필요한 건 스킬 하나로 보입니다. 이유는 {이유}입니다.
> 이건 PC에 아무것도 깔지 않고, Claude 계정에 올려 두고 쓰는 방식입니다.
> 회사 PC든 집이든 로그인만 하면 그대로 있고, 동료에게는 파일 하나만 건네면 됩니다. 폴더도 지시 파일도 없어서 고칠 게 하나뿐입니다.
> 이대로 갈까요, 아니면 더 크게 만들어 보시겠어요?

### 도구

> 필요한 건 버튼 화면이 있는 도구로 보입니다. 이유는 {이유}입니다.
> 주소를 열고 버튼을 누르면 처리되는 화면을 만드는 방식이고, 명령어를 칠 일은 없습니다.
> 이대로 갈까요, 아니면 더 크게 만들어 보시겠어요?

### 에이전트

> 필요한 건 에이전트로 보입니다. 이유는 {이유}입니다.
> 폴더를 두고 무엇을 어떻게 할지 적어 두면, 그 안에서 여러 단계가 이어서 돌아가는 방식입니다.
> 이대로 진행할까요?

에이전트는 제일 큰 갈래라 더 올릴 곳이 없다.
그래서 확인만 받는다.

---

## 7. 판정을 뒤집을 수 있게 둔다

사용자가 더 큰 갈래로 올리고 싶어 하면 **올려 준다.**
말리지 않는다.
다만 원래 판정과 그 이유는 반드시 기록에 남긴다.

뒤집었을 때 기록하는 방법이다.

| 필드 | 값 |
|------|-----|
| `갈래.판정` | 사용자가 고른 갈래 |
| `갈래.선택` | `"상위로 변경"` |
| `갈래.원래권장` | 원래 판정한 갈래 |
| `갈래.이유` | 원래 판정의 이유를 그대로 둔다 |

권장을 그대로 따랐으면 `갈래.선택`은 `"권장대로"`, `갈래.원래권장`은 `null`이다.

올릴 수 있는 방향은 위로만이다.
스킬 → 도구 · 스킬 → 에이전트 · 도구 → 에이전트.
아래로 내리자는 요청이 나오면 그건 판정이 다시 도는 것이므로, 근거가 된 답을 하나 고쳐 받고 처음부터 판정한다.

기획서에는 "권장은 스킬, 선택은 에이전트"처럼 두 가지가 다 보이게 적는다.

## 8. 이 규칙에서 하지 않는 것

| 안 하는 것 | 이유 |
|-----------|------|
| "스킬로 만들까요, 에이전트로 만들까요"라고 직접 묻기 | 사용자가 답할 수 있는 질문이 아니다. 업무를 묻고 이쪽에서 판정한다 |
| 판정을 말없이 적용하기 | 이유를 보여주는 것이 이 대목의 핵심이다 |
| 사용자가 올리겠다는 걸 막기 | 이유는 보여주되 선택은 사용자가 한다 |
| 안쪽 용어를 판정 문장에 쓰기 | 갈래 이름 셋과 부품 이름 외에는 풀어 쓴 말만 쓴다 |
| 판정 근거를 지어내기 | 근거는 받은 답에서만 가져온다. 답이 없으면 신호가 없는 것으로 본다 |
| 되돌아온 경험으로 갈래 올리기 | Q9는 부품 `평가담당`의 근거일 뿐이다. 게이트에서 보지 않는다 |
| 이미 받은 답을 못 들은 것으로 치고 다시 묻기 | 인터뷰가 늘어지고, 근거가 있는데도 낮은 쪽에 머문다 |
| 근거 없이 실행 파일로 올리기 | 설치를 못 한다는 말이 있을 때만이다. 기본값은 로컬 웹앱이다 |
| 스킬 갈래에 폴더로 시키는 실행 방식을 남기기 | 만들지 않는 폴더가 쓰는 법에 나온다 |
