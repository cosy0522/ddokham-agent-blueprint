# 하는 일

`설계도/기획서.md`를 다시 읽어 바뀐 내용을 반영하고, `설계도/설계도.html`과 `설계도/세팅_프롬프트.md`를 다시 만든다.

인터뷰를 다시 하지 않는다.
설계도를 보다가 "이 단계는 사람이 봐야 한다"처럼 고칠 것이 생겼을 때 쓰는 커맨드다.

# 기획서가 없을 때

`설계도/기획서.md`가 없으면 다시 그릴 것이 없다.
`/ddokham-blueprint`를 먼저 써서 기획서를 만들라고 안내하고 끝낸다.
비어 있는 기획서를 새로 만들지 않는다.

# 절차

1. `설계도/기획서.md`를 처음부터 끝까지 읽는다.
2. 이번에 말로 요청받은 수정 사항이 있으면 먼저 `설계도/기획서.md`에 반영하고, 그 기획서를 기준으로 나머지를 만든다.
3. `blueprint-interview` 스킬의 `references/data-schema.md`를 읽고, 기획서 내용을 그 구조의 데이터로 다시 정리한다. 필드 이름과 값을 한 글자도 바꾸지 않는다.
4. 갈래나 부품이 바뀌었으면 같은 스킬의 `references/track-rules.md`와 `references/part-rules.md`로 다시 판정한다.
5. `references/prompt-format.md`대로 `설계도/세팅_프롬프트.md`를 다시 쓰고, 그 본문을 데이터의 `세팅프롬프트` 값에 그대로 넣는다.
6. `blueprint-draw` 스킬로 `설계도/설계도.html`을 다시 만든다.
7. 무엇이 바뀌었는지 한두 줄로 알려 주고, 설계도를 다시 열어 보라고 안내한다.

요청받지 않은 곳은 고쳐 쓰지 않는다.
기획서는 사용자가 직접 고치는 원본이고, 이 커맨드는 그것을 읽어서 나머지 둘을 맞추는 일만 한다.
기획서에 명백한 오류가 보이면 고치지 말고 말로 알려 준다.

# 절대 하지 않는 것

- `CLAUDE.md`를 만들지 않는다.
- 작업 폴더를 만들지 않는다. 설계도에 적히는 폴더 이름도 실제로 만들지 않는다.
- 서브 에이전트나 스킬 정의 파일을 만들지 않는다.
- 설정 파일을 만들지 않고, 초기화 커맨드를 실행하지 않는다.
- 설계한 결과물을 실제로 만들지 않는다. 코드나 스크립트를 쓰지 않는다.
- `설계도/` 밖의 파일을 고치거나 지우지 않는다.
