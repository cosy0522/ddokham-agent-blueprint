# 하는 일

사용자의 업무를 인터뷰해서 무엇을 만들지 판정하고, `설계도/` 폴더에 파일 세 개를 만든다.

`blueprint-interview` 스킬을 읽고 그 절차를 그대로 따른다.
질문 문구·보기·판정 규칙·산출물 형식은 전부 그 스킬과 `references/` 안의 파일에 있다.
여기 없는 내용을 지어내지 않는다.

# 시작하는 법

인사와 함께 바로 0단계로 들어간다.
설정을 묻거나 준비 작업을 시키지 않는다.

0단계는 질문이 아니라 훑어보기다.
현재 폴더의 파일을 훑어 "만들고 싶은 결과물"로 보이는 것을 최대 네 개 골라 후보로 제시한다.
후보로 삼을 파일이 없으면 스킬의 `references/examples.json`에 있는 예시 네 가지를 보여 주고 하나를 고르게 한다.

그다음 1단계부터 4단계까지 질문을 진행하고, 갈래를 판정해 이유를 보여 주고, 부품을 판정한 뒤 산출물 세 개를 만든다.

# 만드는 것

`설계도/` 폴더와 그 안의 파일 세 개뿐이다.

- `설계도/기획서.md`
- `설계도/설계도.html`
- `설계도/세팅_프롬프트.md`

# 절대 하지 않는 것

이 커맨드는 아무것도 초기화하지 않는다.
설계만 하는 단계이고, 실제 세팅은 다음 단계에서 세팅 프롬프트가 한다.

- `CLAUDE.md`를 만들지 않는다.
- 작업 폴더를 만들지 않는다. 설계도에 적히는 폴더 이름도 실제로 만들지 않는다.
- 서브 에이전트나 스킬 정의 파일을 만들지 않는다.
- 설정 파일을 만들지 않고, 초기화 커맨드를 실행하지 않는다.
- 설계한 결과물을 실제로 만들지 않는다. 코드나 스크립트를 쓰지 않는다.
- 폴더에 있던 기존 파일을 고치거나 지우지 않는다. 읽기만 한다.

# 끝낼 때

세 파일의 전체 경로를 알려 주고, 설계도는 더블클릭하면 브라우저에서 열린다고 안내한다.
고칠 것이 있으면 `기획서.md`를 고친 뒤 `/ddokham-blueprint-redraw`를 쓰라고 알려 준다.
