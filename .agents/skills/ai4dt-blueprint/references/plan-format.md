# 기획서 형식

`설계도/기획서.md`의 형식이다. 사용자가 읽고 직접 고치는 문서이며, 강사가 순회하며 보는 것도 이 파일이다.
데이터(`data-schema.md`)를 사람이 읽는 문장으로 옮긴 것이고, 사용자가 이 파일을 고친 뒤 다시 그리기를 실행하면 설계도와 세팅 프롬프트가 이 파일 기준으로 다시 만들어진다.

---

## 지켜야 할 것

| 규칙 | 내용 |
|------|------|
| 섹션 구조 고정 | 여덟 개 섹션을 이 순서 그대로 쓴다. 갈래가 달라도 섹션을 빼거나 더하지 않는다 |
| 제목 문자열 고정 | 섹션 제목과 표의 항목 이름을 바꾸지 않는다. 다시 그리기가 이 제목으로 값을 찾는다 |
| 전문용어 금지 | 스키마·필드·파싱·렌더·서브에이전트 같은 말을 쓰지 않는다. 부품은 아래 표시 이름으로만 부른다 |
| 한 문장 한 줄 | 문장 중간에서 줄을 바꾸지 않는다 |
| 강조 금지 | 별표 강조를 쓰지 않는다 |
| 원문 금지 | 문서 본문·실제 수치·개인정보를 옮기지 않는다. 항목 이름과 규칙만 적는다 |
| 빈 값 표기 | 값이 없으면 칸을 비우지 말고 `아직 안 정함`이라고 적는다 |
| 목록 길이 | 한 목록은 최대 5개. 넘으면 앞 5개만 적고 나머지는 7번 섹션으로 옮긴다 |

### 갈래가 달라도 같은 것과 다른 것

| 구분 | 내용 |
|------|------|
| 같다 | 섹션 8개, 순서, 제목, 표의 항목 이름, 6번 섹션의 부품 6줄 |
| 다르다 | 각 칸에 들어가는 값, 4번 표의 단계 성격, 6번에서 켜지는 부품 |

세 갈래가 같은 틀로 나와야 서로 비교가 되고 강사가 한눈에 본다.

### 부품 표시 이름

기획서에는 왼쪽 이름만 쓴다. 오른쪽은 데이터에서 찾을 때만 쓰는 이름이므로 문서에 노출하지 않는다.

| 문서에 쓰는 이름 | 데이터 항목 |
|-----------------|-----------|
| 서식·절차 스킬 | `스킬` |
| 나눠서 동시에 | `나눠서동시에` |
| 평가 담당 | `평가담당` |
| 보내기 연결 | `보내기연결` |
| 혼자 도는 도구 | `혼자도는도구` |
| 보여주는 페이지 | `보여주는페이지` |

## 전체 골격

```markdown
# {이름}

> {한줄목표}

- 만든 날: {만든날짜}
- 만든 사람: {만든사람}

## 무엇을 만드나
## 결과물
## 무엇으로 만드나
## 어떤 순서로
## 이번에 만들 범위
## 쓰는 부품과 이유
## 다음 단계
## 아직 안 정한 것
```

`만든사람`이 없으면 그 줄을 넣지 않는다.

---

## 1. 무엇을 만드나

갈래 판정과 그 이유가 첫 화면에 온다. 무엇을 만드는 사람인지가 한 줄로 보여야 한다.

```markdown
## 무엇을 만드나

| 항목 | 내용 |
|------|------|
| 만드는 것 | {갈래.판정} |
| 그렇게 본 이유 | {갈래.이유} |
| 어떻게 시키나 | {구성.실행방식} |
| 쓰는 곳 | {구성.폴더를 쉼표로 이은 것} |
```

채우는 법.

| 칸 | 채우는 법 |
|----|----------|
| 만드는 것 | `스킬` `도구` `에이전트` 중 하나를 그대로 적는다 |
| 그렇게 본 이유 | 한 문장. 판정 근거가 된 답을 그대로 쓴다 |
| 쓰는 곳 | 폴더가 비어 있으면 `따로 만드는 폴더 없음`이라고 적는다. 만들지 않을 폴더 이름을 적지 않는다 |

권장과 다른 갈래를 골랐으면 표 아래에 한 줄을 덧붙인다.

```markdown
권장은 {갈래.원래권장}이었고, 선택은 {갈래.판정}이다.
```

갈래별로 이 섹션이 어떻게 채워지는지.

| 갈래 | 어떻게 시키나 | 쓰는 곳 |
|------|-------------|--------|
| 스킬 | Claude 계정에 올려두고 말로 시킨다 | 따로 만드는 폴더 없음 |
| 도구 | 고른 실행 방식을 그대로 적는다 | 따로 만드는 폴더 없음 |
| 에이전트 | 고른 실행 방식을 그대로 적는다 | 폴더 이름을 쉼표로 잇는다 |

---

## 2. 결과물

무엇이 나오고 어디로 가는지, 그리고 다 됐다고 볼 기준이 무엇인지를 적는다.

```markdown
## 결과물

| 항목 | 내용 |
|------|------|
| 이름 | {결과물.이름} |
| 형식 | {결과물.형식} |
| 어디로 가나 | {결과물.전달방식을 쉼표로 이은 것} |
| 받는 사람 | {결과물.받는사람} |
| 얼마나 자주 | {결과물.주기} |

다 됐다고 볼 기준
- {결과물.완성기준 각 항목}

지금까지 되돌아온 이유
- {반려사유 각 항목}
```

채우는 법.

| 칸 | 채우는 법 |
|----|----------|
| 다 됐다고 볼 기준 | 비어 있으면 목록 대신 `아직 안 정함` 한 줄을 적는다 |
| 지금까지 되돌아온 이유 | 비어 있으면 `없음` 한 줄을 적는다 |

되돌아온 이유는 6번의 평가 담당이 검사할 기준이 된다. 두 곳의 문구를 같게 유지한다.

---

## 3. 무엇으로 만드나

입력을 세 갈래로 나눠 적는다. 세 갈래를 합치지 않는다. 매번 바뀌는 자료와 늘 같은 자료는 다루는 방식이 다르다.

```markdown
## 무엇으로 만드나

매번 새로 받는 자료

| 이름 | 형식 | 어디서 가져오나 |
|------|------|---------------|
| {입력.매번바뀜[].이름} | {형식} | {출처} |

늘 참고하는 자료

| 이름 | 형식 |
|------|------|
| {입력.고정참조[].이름} | {형식} |

머릿속에만 있던 규칙
- {입력.머릿속규칙 각 항목}

지시로 적을 것
- {구성.지시요지 각 항목}
```

채우는 법.

| 칸 | 채우는 법 |
|----|----------|
| 어디서 가져오나 | 서로 다른 출처가 몇 개인지가 뒤의 판정 근거다. 모르면 `미정`이라고 적는다 |
| 늘 참고하는 자료 | 없으면 표 대신 `없음` 한 줄 |
| 머릿속에만 있던 규칙 | 비어 있으면 목록 대신 아래 경고 한 줄을 적고, 8번 섹션에도 올린다 |
| 지시로 적을 것 | 머릿속 규칙을 지시 문장으로 옮긴 것이다. 규칙과 문구가 겹쳐도 그대로 둔다 |

머릿속 규칙이 비었을 때 넣는 줄.

```markdown
- 아직 안 정함 — 이 칸이 비면 남이 만든 것 같은 결과가 나온다. 여기부터 채우는 것을 권한다.
```

## 4. 어떤 순서로

지금 이 일을 하는 순서를 그대로 적고, 각 단계를 누가 하는지 붙인다.

```markdown
## 어떤 순서로

| 순서 | 하는 일 | 누가 하나 | 표시 |
|------|--------|----------|------|
| {과정[].순서} | {이름} | {담당} | {표시} |

사람이 볼 곳: {구성.사람확인지점을 쉼표로 이은 것}
```

담당은 아래 말로만 적는다.

| 데이터 값 | 문서에 쓰는 말 |
|----------|--------------|
| `AI` | AI |
| `사람` | 사람 |
| `AI+확인` | AI가 하고 사람이 확인 |

표시 칸에 쓰는 말도 정해 둔다. 여러 개면 쉼표로 잇고, 해당이 없으면 `-`를 적는다.

| 조건 | 표시 |
|------|------|
| 같은 병렬그룹이 둘 이상 | 동시에 진행 |
| 병목 | 제일 오래 걸림 |
| 루프대상이 있음 | {번호}번으로 되돌아감 |
| 이번 범위에 없음 | 이번 범위 밖 |

범위 밖 단계도 표에서 지우지 않는다. 전체 흐름이 보여야 무엇을 남겨 두는지가 보인다.
사람이 볼 곳이 없으면 `없음`이라고 적는다.

---

## 5. 이번에 만들 범위

오늘 만들 것과 남겨 둘 것을 단계 번호와 이름으로 나눠 적는다.

```markdown
## 이번에 만들 범위

이번에 만들 것
- {번호}. {단계 이름}

이번에는 안 만들 것
- {번호}. {단계 이름}
```

두 목록을 합치면 4번 표의 전체 단계가 된다. 겹치는 번호가 있으면 안 된다.
`이번에는 안 만들 것`이 비면 `없음 — 처음부터 끝까지 만든다` 한 줄을 적는다.

---

## 6. 쓰는 부품과 이유

여섯 줄이 항상 있다. 안 쓰는 부품을 지우지 않는다. 무엇을 안 썼는지가 보여야 다음에 무엇을 붙일지가 보인다.

```markdown
## 쓰는 부품과 이유

| 부품 | 쓰나 | 어떻게 쓰나 · 왜 안 쓰나 |
|------|------|----------------------|
| 서식·절차 스킬 | 씀 | {내용을 쉼표로 이은 것} |
| 나눠서 동시에 | 안 씀 | {안쓰는이유} |
| 평가 담당 | 씀 | {기준을 쉼표로 이은 것}을 본다. {종료조건}이면 멈춘다 |
| 보내기 연결 | 씀 | {내용} |
| 혼자 도는 도구 | 안 씀 | {안쓰는이유} |
| 보여주는 페이지 | 안 씀 | {안쓰는이유} |
```

부품 줄 순서를 바꾸지 않는다. 여섯 줄의 순서는 위 표 그대로다.

| 부품 | 쓸 때 적는 것 |
|------|-------------|
| 서식·절차 스킬 | 어떤 형식을 어디에 쓰는지 |
| 나눠서 동시에 | 담당을 몇으로 나누는지와 각 담당 이름 |
| 평가 담당 | 무엇을 보는지와 언제 멈추는지. 멈추는 조건을 비우지 않는다 |
| 보내기 연결 | 무엇으로 보내는지 |
| 혼자 도는 도구 | `버튼 화면으로 만든다` 또는 `실행 파일까지 만든다 — 버튼 화면으로 안 되는 이유: {이유}` |
| 보여주는 페이지 | 무엇을 보여주는 페이지인지 |

켜진 부품이 넷 이상이면 그대로 두지 않는다. 둘만 남기고 나머지는 7번 섹션으로 옮긴 뒤, 6번 표에서는 `안 씀`으로 바꾸고 이유에 `오늘 범위 밖이라 다음으로 미룸`이라고 적는다.
갈래에 따라 켜질 수 있는 부품이 다르다. 스킬 갈래는 서식·절차 스킬만, 도구 갈래는 혼자 도는 도구와 보여주는 페이지만 켜진다. 나머지 줄은 `안 씀`으로 채운다.

---

## 7. 다음 단계

오늘 안 만드는 것과 나중에 붙일 것을 적는다. 마지막 줄에 지금 할 일을 붙인다.

```markdown
## 다음 단계

- {다음단계 각 항목}

지금 할 일: 설계도/세팅_프롬프트.md를 새 세션에 붙여 넣는다.
```

5번의 `이번에는 안 만들 것`과 내용이 겹치면 여기서는 빼고, 5번에만 남긴다.
적을 것이 없으면 목록 대신 `당장은 없음` 한 줄을 적는다.

---

## 8. 아직 안 정한 것

빈 채로 넘어간 것을 숨기지 않는다. 이 목록이 다음 대화의 시작점이 된다.

```markdown
## 아직 안 정한 것

- {미정 각 항목}
```

여기에 반드시 올리는 것.

| 조건 | 올리는 문구 |
|------|-----------|
| 머릿속 규칙이 비었음 | 남이 하면 틀리는 것이 무엇인지 |
| 다 됐다고 볼 기준이 비었음 | 어디까지 되면 다 된 것인지 |
| 자료 출처를 모름 | 어느 자료를 어디서 가져오는지 |

비어 있으면 `없음` 한 줄을 적는다.

## 마지막 줄

문서 맨 끝에 이 한 줄을 넣는다. 문구를 바꾸지 않는다.

```markdown
> 이 문서를 고친 뒤 /ddokham-blueprint-redraw 를 실행하면 설계도와 세팅 프롬프트가 다시 만들어집니다.
```

## 데이터가 들어가는 자리

모든 항목이 어느 섹션에 한 번씩 들어간다. 빠진 항목이 있으면 기획서가 덜 만들어진 것이다.

| 데이터 | 들어가는 곳 |
|--------|-----------|
| `이름` `한줄목표` `만든날짜` `만든사람` | 문서 머리 |
| `갈래.판정` `갈래.이유` `갈래.선택` `갈래.원래권장` | 1 무엇을 만드나 |
| `구성.실행방식` `구성.폴더` | 1 무엇을 만드나 |
| `결과물` 전체 | 2 결과물 |
| `반려사유` | 2 결과물, 6 평가 담당 기준 |
| `입력.매번바뀜` `입력.고정참조` `입력.머릿속규칙` | 3 무엇으로 만드나 |
| `구성.지시요지` | 3 무엇으로 만드나 |
| `과정` 전체 | 4 어떤 순서로 |
| `구성.사람확인지점` | 4 어떤 순서로 |
| `범위.이번에만들것` `범위.다음에` | 5 이번에 만들 범위 |
| `부품` 여섯 개 | 6 쓰는 부품과 이유 |
| `다음단계` | 7 다음 단계 |
| `미정` | 8 아직 안 정한 것 |

`세팅프롬프트`는 기획서에 넣지 않는다. 같은 내용이 두 파일에 있으면 어느 쪽이 원본인지 알 수 없게 된다.

## 완성 예시

세 갈래가 같은 틀에 다르게 채워진다는 것을 보이려는 예시다. 분량을 줄여 적었다.

### 스킬 갈래

```markdown
# 회의 결과 정리 스킬

> 메모를 넣으면 정해진 서식의 회의록으로 만들어 준다

- 만든 날: 2026-07-31

## 무엇을 만드나

| 항목 | 내용 |
|------|------|
| 만드는 것 | 스킬 |
| 그렇게 본 이유 | 자료가 한 곳이고 중간에 확인할 지점이 없어서 |
| 어떻게 시키나 | Claude 계정에 올려두고 말로 시킨다 |
| 쓰는 곳 | 따로 만드는 폴더 없음 |

## 결과물

| 항목 | 내용 |
|------|------|
| 이름 | 회의록 |
| 형식 | docx |
| 어디로 가나 | 파일로 남는다 |
| 받는 사람 | 나 |
| 얼마나 자주 | 건별로 그때그때 |
```
