# 부품 판정 규칙

무엇을 붙일지 정하는 규칙이다.
부품 판정은 **갈래가 확정된 뒤에** 돈다 (`track-rules.md` 참조).

부품은 여섯 개다.
데이터에 쓰는 키와 사용자에게 보이는 이름이 다르다.

| 데이터 키 | 사용자에게 보이는 이름 |
|---------|------------------|
| `스킬` | 서식·절차 스킬 |
| `나눠서동시에` | 나눠서 동시에 |
| `평가담당` | 평가 담당 |
| `보내기연결` | 보내기 연결 |
| `혼자도는도구` | 혼자 도는 도구 |
| `보여주는페이지` | 보여주는 페이지 |

---

## 0. 세 가지 원칙

**다 쓰게 유도하지 않는다.**
조건이 맞을 때만 켜고, 켤 때는 왜 필요한지 한 줄을 붙인다.

**부품을 판정하려고 질문을 새로 만들지 않는다.**
이미 받은 답으로 판정한다.
예외는 하나뿐이다 — 평가 담당의 종료 조건.

**근거가 이미 답 안에 있으면 그 문장을 그대로 근거로 쓴다.**
사용자가 한 말을 판정에 쓰려고 같은 사실을 다시 묻지 않는다.
받은 적 없는 별도의 답을 기다리면, 근거가 있는데도 조건이 안 찬 것으로 처리된다.

**여섯 칸은 항상 존재한다.**
안 쓰는 부품도 키를 지우지 않는다.
`쓴다: false`와 `안쓰는이유`를 채워 여섯 칸을 유지한다.

---

## 1. 판정 순서

1. 갈래에 따라 **판정 범위**를 정한다 (2절)
2. 범위 안 부품만 조건을 본다 (3절~8절)
3. 범위 밖 부품은 곧바로 `쓴다: false` + 안내형 `안쓰는이유` (9절)
4. 켜진 개수를 센다. 넷 이상이면 줄인다 (10절)
5. 켜진 부품이 `과정[]`에 남기는 것을 반영한다 (11절)
6. 머릿속 규칙이 비었는지 확인한다 (12절)

---

## 2. 갈래별 판정 범위

갈래마다 도는 부품이 다르다.

| 갈래 | 조건을 보는 부품 | 자동으로 꺼지는 부품 |
|------|--------------|-----------------|
| 스킬 | `스킬` | 나머지 다섯 개 전부 |
| 도구 | `혼자도는도구` · `보여주는페이지` | `스킬` · `나눠서동시에` · `평가담당` · `보내기연결` |
| 에이전트 | 여섯 개 전부 | 없음 |

스킬 갈래에서 부품을 하나만 보는 이유는, 폴더도 지시 파일도 없는 갈래이기 때문이다.
붙일 자리가 없는 부품을 켜면 설계도와 세팅 프롬프트가 어긋난다.

## 3. 서식·절차 스킬 (`스킬`)

**어느 답으로 판정하나** — Q1 결과물 형식 (`결과물.형식`) · Q5 늘 똑같이 참고하는 자료 (`입력.고정참조`)

**켜는 조건** — 둘 중 하나라도 참이면 켠다.

| 번호 | 조건 |
|------|------|
| K1 | `결과물.형식`이 정해진 문서 형식이다 (`docx` `xlsx` `pptx` `pdf` `hwpx` `csv` 등) |
| K2 | `입력.고정참조`에 서식·양식·기준표가 하나 이상 있다 |

**켜면 채우는 필드**

```json
"스킬": { "쓴다": true, "내용": ["docx — 보고서 서식 출력", "xlsx — 표 읽기"], "안쓰는이유": null }
```

`내용`은 `"형식 — 용도"` 형태의 문자열 배열이다.
형식은 `결과물.형식`과 `입력.매번바뀜[].형식`에서 가져온다.
용도는 읽는 쪽인지 내보내는 쪽인지 한 마디로 적는다.

### 형식에 따라 다음 단계가 하나 붙는다

형식마다 손이 드는 정도가 다르다.

| 결과물 형식 | 처리 |
|-----------|------|
| 널리 쓰이는 문서 형식 (`docx` `xlsx` `pptx` `pdf` `csv`) | 이미 나와 있는 것으로 된다. 켜고 끝낸다 |
| 그 밖의 형식 (`hwpx`처럼 특정 프로그램 전용 형식) | 그 서식을 다룰 스킬을 새로 만들어야 한다. 켜되 `다음단계`에 `"○○ 서식 스킬 만들기"`를 넣는다 |

이미 있는 것으로 되는지 새로 만들어야 하는지를 적어 두지 않으면, 세팅 단계에서 없는 것을 있는 줄 알고 찾는다.
찾다 못 찾으면 그 자리에서 막힌다.

**붙이는 이유 한 줄** — 같은 모양을 매번 다시 설명하지 않기 위해서입니다.

## 4. 나눠서 동시에 (`나눠서동시에`)

**어느 답으로 판정하나** — Q4 자료 출처 (`입력.매번바뀜[].출처`)

**켜는 조건** — 두 조건이 **모두** 참이어야 켠다.

| 번호 | 조건 |
|------|------|
| N1 | 서로 다른 출처가 **3곳 이상** |
| N2 | 그 자료들이 **서로 독립**이다 |

### N2는 반드시 확인하고 넘어간다

**앞 단계 결과가 뒤의 입력이면 켜지 않는다.**
하나를 받아야 다음 걸 받을 수 있는 자료는 동시에 가져올 수 없다.
이걸 확인하지 않고 켜면 설계도에 그려진 대로는 돌아가지 않는다.

확인은 이미 받은 답으로만 한다. 질문을 새로 만들지 않는다.
`과정[]` 초안에서 자료를 모으는 단계가 다른 단계의 결과물을 쓰고 있으면 N2는 거짓이다.
Q4에서 받은 출처가 서로 다른 자리이고 어느 하나가 다른 하나의 결과가 아니면 N2는 참이다.

거짓이면 켜지 않고 `안쓰는이유`에 `"앞 자료가 나와야 다음 자료를 받을 수 있어서"`로 적는다.
받은 답만으로 독립인지 가려지지 않을 때도 켜지 않는다.
확실하지 않을 때는 안 켜는 쪽이 손해가 적다.

**켜면 채우는 필드**

```json
"나눠서동시에": { "쓴다": true, "내용": ["○○ 담당", "○○ 담당", "○○ 담당"], "안쓰는이유": null }
```

`내용`은 담당 이름 배열이다.
출처 하나에 담당 하나를 만든다.
이름은 그 출처에서 가져오는 자료 이름을 따서 짓는다.

**붙이는 이유 한 줄** — 순서대로 하면 오래 걸리는 일을 한꺼번에 하려고요.

## 5. 평가 담당 (`평가담당`)

**어느 답으로 판정하나** — Q9 반려·재작업 (`반려사유`)

**켜는 조건**

| 번호 | 조건 |
|------|------|
| P1 | Q9의 답이 `자주` 또는 `가끔`이다 |

`거의 없다`이면 켜지 않는다.
사유를 적었다면 `반려사유` 배열에는 그대로 남긴다 (설계도에 표시된다).

**Q9는 여기서만 쓴다.**
갈래 판정에는 쓰지 않는다 (`track-rules.md` 1절).
되돌아온 적이 있다는 것은 검사할 기준이 있다는 뜻이지, 더 큰 걸 만들어야 한다는 뜻이 아니다.

### 기준은 새로 묻지 않는다

**반려당했던 사유가 곧 평가 기준이다.**
`반려사유` 배열을 `부품.평가담당.기준`으로 그대로 옮긴다.
표현만 검사 항목처럼 다듬는다.

| `반려사유` | `부품.평가담당.기준` |
|----------|--------------|
| "숫자 근거가 없다고 되돌아옴" | "숫자 근거 유무" |
| "지난번과 비교 설명이 빠졌다고 지적받음" | "지난번 대비 설명 유무" |

### 종료 조건은 반드시 묻는다

평가 담당을 켜기로 하면 **멈출 지점을 묻는다.**
반복을 시킬 때 멈출 지점을 정하지 않으면 끝나지 않는다.

> "평가 담당이 몇 번까지 고치게 할까요? — 지적이 없을 때까지 / 세 번 왕복 / 한 번만"

답을 못 하면 `"세 번 왕복"`을 기본값으로 넣는다.
`종료조건`은 비우지 않는다.

**켜면 채우는 필드**

```json
"평가담당": { "쓴다": true, "기준": ["숫자 근거 유무"], "종료조건": "세 번 왕복", "안쓰는이유": null }
```

**붙이는 이유 한 줄** — 만드는 쪽과 검사하는 쪽을 나누려고요.

## 6. 보내기 연결 (`보내기연결`)

**어느 답으로 판정하나** — Q2 어디로 가나 (`결과물.전달방식`)

**켜는 조건**

| 번호 | 조건 |
|------|------|
| B1 | `결과물.전달방식`에 `"누군가에게 보낸다"`가 들어 있다 |

**켜면 채우는 필드**

```json
"보내기연결": { "쓴다": true, "내용": "메일 발송", "안쓰는이유": null }
```

`내용`은 무엇으로 보내는지 한 마디다.
받는 사람은 `결과물.받는사람`에 이미 있으므로 여기 다시 적지 않는다.

**붙이는 이유 한 줄** — 만드는 데서 끝내지 않고 전달까지 이으려고요.

## 7. 혼자 도는 도구 (`혼자도는도구`)

**어느 답으로 판정하나** — Q2 어디로 가나 (`결과물.전달방식`) · Q11 실행 방식 (`구성.실행방식`) · 인터뷰에서 받은 답 전체

**켜는 조건**

| 번호 | 조건 |
|------|------|
| H1 | 갈래가 `도구`다 |

도구 갈래이면 이 부품은 켠다.
`단계`의 기본값은 `"로컬 웹앱"`이다.

**`단계`를 `"실행 파일"`로 올리는 조건** — 둘 다 참일 때만이다.

| 번호 | 조건 |
|------|------|
| H2 | 나눠 줄 상대가 있다 — `결과물.전달방식`에 `"다른 사람이 각자 실행해서 쓴다"`가 있거나, `구성.실행방식`이 `"다른 사람이 각자 실행"`이다 |
| H3 | 그 사람들이 설치를 못 한다는 사실이 **이미 받은 답 안에** 있다 |

### 이유를 따로 묻지 않는다

**H3의 근거가 된 그 문장이 곧 `웹앱으로안되는이유`다.**
사용자가 설치를 못 한다고 이미 말했으면 그 말이 이유다.
"웹앱으로는 왜 안 되나요"를 따로 묻고 그 답을 기다리지 않는다.
받은 적 없는 답을 조건으로 걸어 두면, 근거가 있는데도 로컬 웹앱에 머문다.

문장은 받은 그대로 한 줄로 옮긴다.
원문에 없는 이유를 지어내지 않는다.
어느 질문의 답이었는지도 따지지 않는다. 인터뷰 도중 어디서 나온 말이어도 된다.

### 무엇을 설치 못 한다는 사실로 보나

| 이런 말이면 H3는 참 | 이런 말은 H3가 아니다 |
|------------------|------------------|
| PC에 뭘 설치하지 못한다 | 컴퓨터를 잘 모른다 |
| 설치 권한이 없다 | 여러 명이 나눠 쓴다 |
| 보안 때문에 프로그램을 못 받는다 | 각자 자기 것을 돌려 본다 (이건 H2다) |
| 회사 PC라 설치가 막혀 있다 | 설치가 번거롭다 |

왼쪽 칸은 못 하는 것이고 오른쪽 칸은 안 익숙하거나 귀찮은 것이다.
오른쪽 칸의 말만 받았으면 `단계`는 `"로컬 웹앱"`이다.

### H3가 없으면 로컬 웹앱으로 확정한다

H2는 참인데 설치 이야기가 어디에도 없으면 그대로 `"로컬 웹앱"`이다.
이때 설치가 되는지를 새로 묻지 않는다 (0절 원칙).
남에게 나눠 준다는 것만으로는 올리지 않는다. 설치가 되는 사람에게는 웹앱이 더 낫다.

실행 파일은 만들기가 무겁고 고치기도 어려워서, 근거 없이 올리면 손해가 크다.
사용자가 나중에 설치가 안 된다고 말하면, 그때 H3가 채워진 것으로 보고 올린다.

**켜면 채우는 필드**

```json
"혼자도는도구": { "쓴다": true, "단계": "로컬 웹앱", "웹앱으로안되는이유": null, "안쓰는이유": null }
```

`단계`가 `"실행 파일"`이면 `웹앱으로안되는이유`는 비울 수 없다.
넣을 문장이 없으면 `단계`를 `"로컬 웹앱"`으로 되돌린다.

**붙이는 이유 한 줄** — 컴퓨터를 잘 모르는 분도 더블클릭으로 쓰게 하려고요.

## 8. 보여주는 페이지 (`보여주는페이지`)

**어느 답으로 판정하나** — Q2 어디로 가나 (`결과물.전달방식`)

**켜는 조건**

| 번호 | 조건 |
|------|------|
| V1 | `결과물.전달방식`에 `"여러 사람이 보는 화면에 올린다"`가 들어 있다 |

**켜면 채우는 필드**

```json
"보여주는페이지": { "쓴다": true, "내용": "이번 달 집계 결과 화면", "안쓰는이유": null }
```

`내용`은 무엇을 보여주는 페이지인지 한 마디다.

**붙이는 이유 한 줄** — 파일을 돌리는 대신 링크 하나로 보여주려고요.

## 9. 안 쓰는 부품 처리

**여섯 칸을 유지한다.**
안 쓰는 부품도 `쓴다: false` + `안쓰는이유`를 채운다.
안 쓰는 부품을 지우면 깔끔해지지만, 내가 뭘 안 썼는지가 안 보인다.
회색 칸의 이유가 다음에 손댈 목록이 된다.

`안쓰는이유`는 두 가지로 갈린다.

### (가) 범위 안인데 조건이 안 맞은 경우

그 사람의 답을 근거로 한 구절로 적는다.

| 부품 | 예 |
|------|-----|
| `나눠서동시에` | "자료를 한 곳에서만 받아서" |
| `평가담당` | "되돌아온 적이 없어서" |
| `보내기연결` | "내가 보관하는 문서라" |
| `보여주는페이지` | "받는 사람이 한 명이라" |

### (나) 갈래 때문에 범위 밖인 경우

언제 쓰는 부품인지 안내형으로 적는다.
"이럴 때 씁니다"가 보여야 다음에 올릴 때 참고가 된다.

| 부품 | 안내 문구 |
|------|---------|
| `스킬` | "결과물 서식이 정해져 있을 때 씁니다" |
| `나눠서동시에` | "자료를 세 곳 이상에서 따로 받아올 때 씁니다" |
| `평가담당` | "결과물이 되돌아온 적이 있을 때 씁니다" |
| `보내기연결` | "만든 걸 누군가에게 보내야 끝날 때 씁니다" |
| `혼자도는도구` | "다른 사람이 각자 실행해서 써야 할 때 씁니다" |
| `보여주는페이지` | "여러 사람이 같은 화면을 봐야 할 때 씁니다" |

## 10. 넷 이상이면 줄인다

`쓴다: true`인 부품을 센다.
**넷 이상이면 경고한다.**

> "오늘 남은 시간으로는 여기까지 다 못 만듭니다. 어느 둘부터 만들까요?"

배운 걸 다 얹는 설계가 가장 위험하다.

고른 둘만 남기고 나머지는 이렇게 옮긴다.

| 처리 | 내용 |
|------|------|
| `쓴다` | `false`로 바꾼다 |
| 값 칸 | `내용`·`기준`·`종료조건`·`단계`를 안 쓸 때의 모양으로 되돌린다. 배열은 `[]`, 나머지는 `null` |
| `안쓰는이유` | `"오늘 범위 밖이라 다음으로 미룸"` |
| `다음단계` | `"○○ 붙이기"`에 이미 받아 둔 내용을 괄호로 붙여 배열에 추가한다 |

### 받아 둔 내용은 다음단계 문장으로 옮긴다

안 쓰기로 한 칸에 값을 남기지 않는다.
데이터 계약에서 `쓴다: false`인 칸은 값 칸이 비어 있는 모양이고, 설계도도 그 칸을 회색으로 그리면서 `안쓰는이유`만 보여 준다.
값만 남겨 두면 어디에도 뜨지 않아, 남긴 줄 알았던 내용이 다음에 켤 때 사라진 뒤다.

받아 둔 것은 `다음단계` 문장 안에 그대로 적는다.
그러면 설계도 아래쪽에 보이고, 다음에 켤 때 다시 물을 필요가 없다.

| 옮기기 전 | `다음단계`에 넣는 문장 |
|----------|------------------|
| 평가 담당 · 기준 `["숫자 근거 유무"]` · 종료조건 `"세 번 왕복"` | `"평가 담당 붙이기 (기준: 숫자 근거 유무, 세 번 왕복)"` |
| 나눠서 동시에 · 내용 `["실적 담당", "지출 담당"]` | `"나눠서 동시에 붙이기 (실적 담당, 지출 담당)"` |

## 11. 켜진 부품이 과정에 남기는 것

부품을 켜면 `과정[]`에도 반영한다.
설계도의 그림이 여기서 나온다.

| 부품 | `과정[]`에 반영할 것 |
|------|-------------------|
| `나눠서동시에` | 자료를 모으는 단계들에 같은 `병렬그룹` 번호를 준다 |
| `평가담당` | 평가 단계를 하나 두고, 그 단계의 `루프대상`에 되돌아갈 단계 번호를 넣는다 |
| `보내기연결` | 마지막에 보내는 단계를 둔다 |
| `혼자도는도구` | 버튼을 누른 뒤 일어나는 처리 순서를 단계로 적는다 |

순차로 도는 단계의 `병렬그룹`은 `null`이다.
평가 단계가 아닌 단계의 `루프대상`도 `null`이다.

## 12. 머릿속 규칙이 비면 경고한다

`입력.머릿속규칙`이 빈 배열이면 그냥 넘어가지 않는다.

이 칸이 만든 물건이 쓸모 있느냐를 가른다.
비어 있으면 누가 만들어도 되는 결과물이 나온다.

한 번 더 묻는다.

> "이걸 다른 사람에게 시켰을 때 꼭 틀리는 게 하나쯤 있으실 텐데요. 표현이든 숫자 처리든 한 줄만 적어 주세요."

그래도 답이 없으면 `미정` 배열에 `"머릿속 규칙"`을 넣는다.
설계도가 이 항목에 경고를 띄운다.

## 13. 이 규칙에서 하지 않는 것

| 안 하는 것 | 이유 |
|-----------|------|
| 부품을 직접 묻기 | 답할 수 있는 질문이 아니다. 업무를 묻고 이쪽에서 판정한다 |
| 배운 부품을 다 얹기 | 조건이 맞는 것만 켠다. 넷 이상이면 줄인다 |
| 출처가 하나인데 나눠서 동시에를 켜기 | 동시에 할 게 없다 |
| 독립 확인 없이 나눠서 동시에를 켜기 | 앞 결과가 뒤의 입력이면 그대로는 돌아가지 않는다 |
| 종료 조건 없이 평가 담당을 켜기 | 멈출 지점이 없으면 끝나지 않는다 |
| 되돌아온 경험으로 갈래를 올리기 | Q9는 평가 담당의 근거일 뿐이다. 갈래는 다른 답으로 정해진다 |
| 이미 받은 답을 못 들은 것으로 치고 다시 묻기 | 인터뷰가 늘어지고, 근거가 있는데도 낮은 쪽에 머문다 |
| 근거 없이 실행 파일로 올리기 | 설치를 못 한다는 말이 있을 때만이다. 기본값은 로컬 웹앱이다 |
| 안 쓰는 부품의 칸을 지우기 | 뭘 안 썼는지가 다음 단계 목록이 된다 |
| 안 쓰기로 한 칸에 값을 남겨 두기 | 데이터 계약과 어긋난다. 받아 둔 내용은 `다음단계` 문장으로 옮긴다 |
| 갈래 범위 밖 부품을 켜기 | 붙일 자리가 없어서 설계도와 세팅 지시가 어긋난다 |
| 안쪽 용어를 사용자에게 말하기 | 부품은 위 표의 보이는 이름으로만 부른다 |
